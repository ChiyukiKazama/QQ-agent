# 系统状态

确定性插件，不使用模型、不会修改人设。群聊中 @机器人发送“状态”或“系统状态”；在已允许的私聊中可以直接发送这两个指令。

回复为一条纯文本，包含两个区块：“系统状态”（系统版本、启动时间、运行时长）和“资源监控”（CPU 型号/核心线程数/使用率/当前频率、内存及磁盘使用量）。CPU 当前频率显示在“使用”一行，存储空间放在资源监控底部。图片、合并转发和任意命令执行均不参与。

Windows 使用 Node.js 系统信息和固定的只读 CIM 查询；CPU 占用率按约 500ms 的实际计数差计算。仅显示本地固定磁盘。GB 数值按 1024³ 字节换算。CIM 读取失败时保留可取得的数据，缺少的项目标为“暂不可用”，不猜测核心数。其他系统使用 Node.js 基本信息与根分区统计。

Windows 查询总限时 15 秒，为开机后首次启动 PowerShell/CIM 留出余量。核心线程数、磁盘、系统信息和实际频率各自处理错误并逐项输出；即使某项失败或整个进程超时，已经完成的项目仍然保留。单项 CIM 查询限时 5 秒，失败原因写入 `[system-status]` 应用日志。每次指令重新读取实时数据，不用旧的频率或磁盘使用量伪装成功。

Windows 当前频率读取系统性能计数器 `Processor Information(_Total) / ActualFrequency`，按 GHz 展示系统汇总的实际频率，用于对照任务管理器的 CPU“速度”。本机对照时，该值与任务管理器均明显低于旧的 `ProcessorFrequency` 值；采样时刻与刷新周期不同，数值不保证逐次完全一致。不读取最高核心频率，也不依赖任务管理器进程运行。频率计数器不可用时单独标为“暂不可用”，其余状态照常显示。未用 `Win32_Processor.CurrentClockSpeed` 作实时频率回退；[微软文档](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-processor)说明该字段来自 SMBIOS。

开关在“插件 → 系统状态”。沿用聊天白名单、成员屏蔽、全局暂停和普通发送队列的限频、去重与历史存档。暂停期间命令被消费但不回复，避免恢复后由模型重复处理。普通聊天不受影响。

插件通过 `message.command` 提供同步匹配器，返回 `{ name, reply }`；核心负责消费消息、后台执行、会话记录和发送。只有完整命令触发，群聊以协议中的 @机器人标记为准。
